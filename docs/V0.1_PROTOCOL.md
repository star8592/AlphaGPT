# AlphaFactory V0.1 — Falsification-First Protocol

## Objective

The project succeeds only if it discovers at least one factor that survives a pre-declared, fully sealed out-of-sample holdout after realistic trading costs.

## Data protocol

1. Every observation must be point-in-time.
2. Historical universes must be reconstructed from information available at that historical timestamp.
3. Delisted, dead, illiquid, or failed assets are not silently removed from history.
4. Missing historical values remain missing unless an explicitly causal imputation rule is declared before the experiment.
5. Corporate-action / token-migration / symbol mapping must be timestamped.

## Temporal protocol

The development process sees only development data.

Recommended first experiment:

- Development / search: 2017-01-01 through 2023-12-31
- Internal validation: walk-forward folds inside the development period
- Sealed holdout: 2024-01-01 onward, with the exact terminal date frozen when the canonical dataset is built

The exact date ranges may change if data availability requires it, but they must be frozen **before** the search begins. Once the holdout is opened, it is never reused as development data for V0.1.

## Leakage rules

Forbidden examples include:

- Full-sample mean / standard deviation / median / MAD used to normalize historical observations.
- Today's survivor or trending list used to define yesterday's tradable universe.
- Backfilling warm-up windows from future observations.
- Choosing thresholds after inspecting holdout results.
- Using revised data when the unrevised point-in-time release was what a trader actually saw.

The core invariant is testable:

> Mutating observations strictly after timestamp t must not alter a factor value at or before t.

## Search protocol

V0.1 starts with deliberately simple searchers. Search sophistication is not a success criterion.

Candidate progression:

1. Hand-authored control formulas.
2. Deterministic random formula generation.
3. Genetic programming.
4. Only later: RL / transformer / LLM hypothesis generation.

Every formula gets a canonical representation and deterministic stable hash so duplicate discoveries can be rejected.

## Evaluation protocol

A candidate is not ranked by raw cumulative return alone.

Minimum evaluation set:

- Rank IC.
- IC stability through time.
- Turnover.
- Explicit fees.
- Explicit slippage.
- Carry / funding where relevant.
- Maximum drawdown when converted into a tradable portfolio rule.
- Cross-period stability.
- Cross-asset stability where the hypothesis claims generality.

Later V0.x gates will add multiple-testing controls (FDR), PBO / deflated Sharpe, capacity, and regime-conditioned robustness.

## Walk-forward rules

Internal validation uses expanding training windows with explicit purge and embargo gaps. Search code can consume training and validation folds, but never the final holdout.

## V0.1 pass/fail

PASS requires all of the following:

1. At least one automatically discovered factor survives the sealed holdout with the pre-declared sign.
2. Its holdout effect remains after declared costs.
3. It is not dependent on one isolated timestamp or asset.
4. No leakage invariant is violated.
5. The exact experiment is reproducible from immutable data fingerprints, formula hash, configuration, and seed.

Otherwise V0.1 is FAIL.

A FAIL is a valid research result. The project must not lower thresholds or redefine the holdout after observing failure.

## Capital policy

V0.1 is research-only. No exchange private key, wallet private key, or live-order capability belongs in this milestone.
